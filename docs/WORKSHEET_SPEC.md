# Спецификация формата учебных рабочих листов (Worksheet Specification)

Настоящий документ определяет структуру, синтаксис и правила валидации файлов интерактивных рабочих листов веб-лаборатории `ai-resistant-lab`.

---

## 1. Общие принципы

1. **Формат данных:** Рабочие листы описываются в формате **JSON** (UTF-8).
2. **Модульность:** Каждый рабочий лист может существовать как отдельный файл (`.json`), так и в составе пакета (массив объектов `[ {...}, {...} ]`).
3. **Критериальное соответствие:** Каждый лист ориентирован на конкретные цели Типовой учебной программы (ТУП РК) и содержит рубрику формативного оценивания с суммой ровно **10 баллов**.
4. **ИИ-резистентность:** Задания разделяются на 4 дидактические модели:
   - `trace`: Ручная пошаговая трассировка ветвлений и циклов.
   - `debug`: Направленная отладка (дебаггинг) дефектного кода.
   - `constraint`: Алгоритмизация с жесткими дидактическими запретами синтаксиса.
   - `audit`: Экспертная верификация и аудит решения генеративного ИИ.

---

## 2. Корневые поля рабочего листа

| Поле | Тип | Обязательное | Описание | Пример |
| :--- | :--- | :---: | :--- | :--- |
| `id` | `string` / `number` | **Да** | Уникальный идентификатор листа в системе | `1` или `"sheet-nested-loops"` |
| `grade` | `number` | **Да** | Параллель классов (7, 8, 9, 10, 11) | `8` |
| `sheetNumber` | `number` | **Да** | Порядковый номер листа | `3` |
| `title` | `string` | **Да** | Название рабочего листа | `"Программирование циклов for"` |
| `topic` | `string` | **Да** | Тема урока по ТУП РК | `"Цикл со счетчиком for и range()"` |
| `learningObjectives` | `string` | **Да** | Коды целей обучения ГОСО/ТУП | `"8.3.3.1, 8.3.3.2"` |
| `tasks` | `Array<Task>` | **Да** | Массив заданий (от 1 до 4 заданий) | `[...]` |
| `rubric` | `Array<Descriptor>` | **Да** | Таблица дескрипторов (сумма 10 баллов) | `[...]` |

---

## 3. Спецификация типов заданий (`Task`)

### Общие поля любого задания
- `id` (`string`): Уникальный ID задания (напр. `"1-1"`).
- `taskNumber` (`number`): Номер задания на листе (1, 2, 3...).
- `type` (`string`): Одно из: `"trace"`, `"debug"`, `"constraint"`, `"audit"`.
- `title` (`string`): Заголовок задания.
- `model` (`string`): Название дидактической модели.
- `description` (`string`): Текст условия задачи для учащегося.

---

### Модель 1: Трассировка (`type: "trace"`)
Используется для ручного пошагового отслеживания памяти и ветвлений.

#### Вариант А: Трассировка ветвлений (`traceTests`)
```json
{
  "code": "v = int(input())\n...",
  "defaultInputs": ["6", "0"],
  "traceTests": [
    {
      "testNum": 1,
      "inputs": "v = 6, k = 0",
      "branchHint": "if v < 7",
      "expectedBranch": "v < 7",
      "expectedCost": 0,
      "points": 0.5
    }
  ],
  "conceptQuestion": {
    "text": "Почему при возрасте v = 6 социальная карта не влияет на cost?",
    "keywords": ["первое условие", "раньше", "выход"],
    "modelAnswer": "Первое условие истинно, блок elif пропускается.",
    "points": 1
  }
}
```

#### Вариант Б: Трассировка цикла со счетчиком (`traceSteps`)
```json
{
  "code": "s = 0\nfor i in range(1, 6):\n    s = s + i",
  "traceSteps": [
    { "step": 1, "i": 1, "cond": "1 % 2 != 0 -> Да", "s": 1, "points": 1 },
    { "step": 2, "i": 2, "cond": "2 % 2 != 0 -> Нет", "s": 1, "points": 1 }
  ]
}
```

---

### Модель 2: Направленная отладка (`type: "debug"`)
Используется для локализации дефектов и исправления некорректного кода.

```json
{
  "buggyCode": "current_year = input()\nbirth_year = input()\nage = current_year - birth_year",
  "questions": [
    {
      "id": "q1",
      "text": "В каких строках допущена ошибка?",
      "expected": "1, 2",
      "points": 1
    },
    {
      "id": "q2",
      "text": "Какая ошибка возникает и почему?",
      "expected": "TypeError: input() возвращает str, вычитание невозможно.",
      "points": 2
    }
  ],
  "fixedCodeTemplate": "current_year = int(input())\nbirth_year = int(input())\nage = current_year - birth_year",
  "testInputs": ["2026", "2008"],
  "expectedOutput": "Доступ разрешен",
  "points": 2
}
```

---

### Модель 3: Дидактические ограничения (`type: "constraint"`)
Задачи, блокирующие стандартные «быстрые» ответы нейросетей за счет запрета синтаксических конструкций.

```json
{
  "bannedKeywords": ["max", "min", "and", "sorted", "["],
  "starterCode": "a = int(input())\nb = int(input())\nc = int(input())\n\n# Напишите код только на вложенных if-else:\n",
  "testCases": [
    { "inputs": ["5", "9", "2"], "expected": "9" },
    { "inputs": ["15", "4", "7"], "expected": "15" }
  ],
  "conceptQuestion": {
    "text": "Почему в ветке elif age <= 15 не нужно повторно проверять age >= 7?",
    "expected": "Предыдущий if уже отсек все значения строго меньше 7."
  },
  "points": 5
}
```

---

### Модель 4: Критический аудит ИИ (`type: "audit"`)
Формирует навык верификации кода генеративных языковых моделей (LLM).

```json
{
  "aiPrompt": "Напиши код фильтрации четных чисел без sum()...",
  "aiOutputCode": "# Ответ ChatGPT:\nnums = [1, 2, 3, 4]\nres = list(filter(lambda x: x % 2 == 0, nums))",
  "aiDefects": [
    "Использована функция filter() и lambda, не входящие в программу 9 класса",
    "Проигнорирован дидактический запрет задачи"
  ],
  "points": 5
}
```

---

## 4. Спецификация рубрики формативного оценивания (`rubric`)

Каждый рабочий лист обязан содержать массив дескрипторов:
```json
"rubric": [
  {
    "criterion": "Трассировка ветвления",
    "descriptor": "Определяет значение cost для тестов 1 и 2",
    "points": 1
  },
  {
    "criterion": "Поиск и исправление ошибок",
    "descriptor": "Точно указывает номера строк с некорректным типом данных",
    "points": 1
  }
]
```
> **Правило валидации:** Сумма полей `points` всех дескрипторов рубрики должна составлять ровно **10 баллов** в соответствии со шкалой формативного оценивания школ РК.

---

## 5. Порядок импорта и парсинга в приложении

1. Приложение считывает JSON через файловый загрузчик (`<input type="file">`), перетаскивание (Drag & Drop) или вставку текста.
2. Модуль `WorksheetParser.validate(data)` проверяет:
   - Корректность JSON-синтаксиса;
   - Наличие обязательных полей верхнего уровня;
   - Валидность массива `tasks` и типов каждого задания;
   - Сумму баллов рубрики (с предупреждением, если не равно 10).
3. При успешной валидации объект сохраняется в `WorksheetStore` (персистентно в `localStorage`).
4. Селектор рабочих листов автоматически обновляется, делая новый лист доступным для решения учащимся.
